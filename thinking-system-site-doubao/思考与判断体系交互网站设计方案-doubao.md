# 《思考与判断体系》交互式网站 · 设计方案

> **方案代号**：doubao 独立版
> **设计原则**：本方案独立提出，**未参考** `thinking-system-site-qoder`、`thinking-system-site-qwen`、`thinking-system-site-workbuddy` 三份已有方案；内容事实全部取自 `thinking_docs/` 下 8 份总结文档（主总结 1 份 + 子主题总结 7 份），无虚构信息。
> **配套演示**：同目录下 `主页概念预览.html` 为本方案主页核心交互的可点击概念演示（非最终站点），供评审时直观体验。

## 一、方案一句话

> **把《思考与判断体系》建成一座"可运行的认知操作系统"：主页是一张可钻取的六层系统总装图，7 个子主题页是各层的模块规格书，四种探索模式让访客既能一眼看到体系全貌，又能深入每一个子主题的精髓，并让"浏览这个网站"本身成为一次对体系的实践。**

## 二、设计定位与目标

| 目标 | 内涵 | 失败的表现 |

## 三、核心创意：网站 = 认知操作系统的运行实例

### 3.1 为什么是"认知操作系统"

主文档对体系的最终定义原文即是：

> **"一套能够独立、持续、可修正地形成判断的认知操作系统。"**

因此设计不另造隐喻，而是**把主文档自己的定义贯彻到底**：网站的信息架构、交互方式、视觉语言全部与"操作系统"同构——浏览网站的动作序列（进入系统 → 查看结构 → 运行流程 → 进入模块 → 返回校准），恰好就是体系本身的运行序列（审题 → 拆解 → 论证 → 判断 → 对话 → 修正）。**网站即系统，这就是本项目"自反性"特质在交付物上的第一次实践。**

### 3.2 体系六层 × 操作系统组件映射表

| 体系层 | 对应 OS 组件 | 网站中的呈现 |
|---|---|---|
| 第零层 · 元层（自反与制衡） | 系统诊断 / 自修复模块 | "自省模式"开关；每个页面阅读后弹出的 B 轨道校准问题 |
| 第一层 · 认知原则（批判性思维） | 内核与安全边界（启动时校验） | 层堆栈的最底层基座；子页《批判性思维》 |
| 第二层 · 问题处理（结构化思维） | 进程调度 / 任务分解 | 层堆栈第二层；子页《结构化 × 工程化》工具箱 |
| 第三层 · 讨论机制（基线 + 框架 + 模型） | 通信协议（握手 + 报文格式） | 层堆栈第三层；子页《讨论基线》 |
| 第四层 · 执行机制（工程化思维） | 运行时环境与工具链 | 层堆栈第四层；子页《结构化 × 工程化》流程部分 |
| 第五层 · 最终能力（个人判断体系） | 应用层（用户可交互的界面） | 层堆栈顶层；子页《判断体系构建》《AI 与个人边界》 |
| 对话 | I/O 接口（与真实世界交换数据） | 主循环演示中唯一"亮色"环节；子页《对话实践》 |
| 持续迭代 | 系统更新循环 | 主循环动画的闭环回到起点 |

### 3.3 "网站即系统"的三个自反设计

1. **自省模式（第零层进网站）**：开启后，每读完一个子页，页面底部会出现一个 B 轨道问题（如"这个解释是否压扁了某种不确定性？"），回答不进入任何数据库，只在当下迫使读者完成一次"总检验"。网站用体系自身的方法论来约束对体系的阅读——这是其他方案不会做、也最难复制的一层。
2. **探索足迹即证据链**：网站记录读者本次访问的路径（层 → 子页 → 组件），在自省模式下回放为一条"我的审题链"，并提示"你停留最久的是结构化页面"——把"检查自己的判断过程"从理念变成可见行为。
3. **内容一源多用**：8 份总结的结构化数据只存一份 JSON，同一数据渲染为叙事、卡片、图表、清单、交互组件五种形态。数据层、渲染层、交互层分离——这正是"工程化思维"（把依赖临场的内容组织变成稳定可复用的流程）在内容管理上的同构实践。

## 五、主页设计：体系全景总装图

主页自上而下 5 个区块，与《思考与判断体系-总结.md》的三部分内容一一对应：

### 5.1 页面结构

```
┌─────────────────────────────────────────────────┐
│ ① Hero：核心命题 + 主循环轨道动画（11 步）        │ ← 主总结·核心命题 + 主线
├─────────────────────────────────────────────────┤
│ ② 系统架构交互图：六层堆栈（核心组件）            │ ← 主总结·五层体系结构
│    元层 / 认知原则 / 问题处理 / 讨论机制          │
│    / 执行机制 / 最终能力 + 对话接口              │
├─────────────────────────────────────────────────┤
│ ③ 四个根问题聚合视图                             │ ← 主总结·三个(四)个根问题
├─────────────────────────────────────────────────┤
│ ④ 子主题入口墙：7 张卡片（页名 + 一句话精髓）     │ ← 七份子主题总结入口
├─────────────────────────────────────────────────┤
│ ⑤ 全局探索导航：模式切换 / 搜索 / 足迹            │ ← 全站常驻
└─────────────────────────────────────────────────┘
```

### 5.2 核心交互一：六层堆栈钻取（主页心脏）

- **形态**：六层纵向堆叠，元层悬浮于顶层之上（标记"第零层"），对话接口以银白色横条"横跨"五层右侧——体现"对话不是平行章节，而是横跨五层的应用层"。
- **默认状态**：每层左侧显示层名 + 回答的问题（如第一层"我应该如何面对问题？"），右侧显示 2–3 个关键词。不操作即可读懂全貌。
- **点击任一层**：该层右侧滑出抽屉面板，显示四栏——①要解决的问题 ②核心概念 ③工具箱（如第二层：三类模型层级链 / 四层抽象 / 五种解释结构）④关键词。抽屉底部是"进入相关子页"按钮（1–3 个），点击即跳转子页。
- **双联动画**：层切换采用"升降梯"动效（向下钻取时上层淡出、下层升起），直观表达"层"的深度关系；动画可被点击打断，不强制等待。

### 5.3 核心交互二：主循环运行演示（11 步）

将完备版主线做成可运行的步进器，默认播放第 1 步（静态可读），提供 **播放 / 暂停 / 上一步 / 下一步 / 重置**：

> 面对现实 → 审辨性审题 → 结构化拆解 → 四基线校验 → 建模与模型转换 → 证据检验 → 形成带证伪条件的判断 → 对话接受检验 → 双轨制衡 → 修正规则、沉淀笔记 → 循环迭代（回到起点）

- 每步行进时：该步高亮 + 底部状态栏显示"当前位于第 X 层" + 弹出该层一句话核心。
- 第 8 步"对话接受检验"是唯一以银白亮色显示的步骤——提醒读者对话是系统唯一的"真实世界接口"。
- 播放完毕停在起点，形成闭环，呼应体系最重要的特征：**循环性**。

### 5.4 核心交互三：四个根问题聚合视图

- 四张卡片：**我如何知道？**（认识论）/ **我如何思考？**（方法论）/ **我如何判断？**（实践）/ **我如何校准思考者自身？**（元问题）。
- 点击任一卡片：卡片展开为两栏——左栏列出该根问题聚合的层（如"我如何知道" → 第一层、第三层），右栏列出相关子页；同时上方层堆栈自动高亮对应层。
- 这一视图提供"第三条探索入口"，照顾"想按问题找答案"而非"按结构学习"的读者。

### 5.5 子主题入口墙

7 张卡片，每张包含：页名、所属层徽标、来源总结文件名（小字标注）、一句话精髓（取自各总结的"一句话核心"）。卡片按体系层序排列（元层 → 第一层 → 应用层 → 第三层 → 第二+四层 → 第五层 ×2），而非按文件名字母序——入口墙本身就是一次对体系的排序。

### 6.2 七个子页及特色交互设计

| 子页 | 来源总结 | 一句话精髓（页头引言） | 特色交互组件 |
|---|---|---|---|
| **批判性思维** | 批判性思维-总结.md | 批判性思维的本质不是"批评"，而是"审辨" | ① **四对象检查轮盘**：事实 / 逻辑 / 前提 / 结论四个扇区，点击任一扇区旋转聚焦并显示对应检查问题（"这是真的吗？证据可靠吗？"）② **相信程度校准器**：拖动"证据强度"滑块（弱→强），结论置信度从"暂不判断"渐变到"高度可信"，并显示"什么证据会让我改变判断"输入框——把"比例性：校准相信程度"变成可操作的手感 |
| **对话实践** | 如何有效开展批判性思维的对话-总结.md | 把"回应"变成一套可操作的对话结构 | ① **八步对话流程步进器**：理解→审题→结构化→证据→模型→反证→判断→对话，每步给出可套用句式（如审题："你认为……的依据是什么？"）② **三语境切换器**：职场 / 亲密关系 / 公共议题三档，切换后同一议题的回应模板实时变化（职场先谈条件、亲密关系先谈感受、公共议题先谈适用范围） |
| **讨论基线** | 讨论问题的三大基线-总结.md | 讨论的最终标准不是"说服对方"，而是"认知增量" | ① **讨论精度滑块**：从"闲聊"拖到"数学证明"，四基线（概念/标准/事实/逻辑）的精度要求逐条实时变化（误差容忍光谱可视化）② **四基线检查清单**：对一个示例议题逐项勾选（概念统一了吗？标准显式吗？事实可验证吗？推理完整吗？），实时给出"讨论资格"评分与判定 ③ **退出讨论判定**：四个"讨论无效"信号作为四个开关，任一命中即提示"该退出，退出≠认输" |
| **结构化 × 工程化** | 分析结构化思维和工程化思维的定义、异同和具体场景-总结.md | 结构化思维解决"看清问题"，工程化思维解决"改变现实" | ① **三类模型层级链交互图**：现实问题→问题模型→信息模型→数学模型→决策，逐节点点击展开定义与三要素（变量/关系/边界）② **四层抽象钻取器**：事实层→功能层→逻辑层→原理层，逐层下钻，每层附"数据可视化对应"示例 ③ **五种解释结构切换器**：拆解/因果/公式/流程/方案五张卡，切换显示对应"回答的问题 + 典型句式"（如公式："GMV = 流量 × 转化率 × 客单价"） |
| **思考者特质** | 思考项目特质-总结.md | 思考能力已经不是瓶颈，思考的自我约束机制才是 | ① **双轨引擎 A/B 切换演示**：轨道 A（A1 结构拆解→A2 对抗压力→A3 尺度迁移）与轨道 B（B1 不可解释槽位→B2 体验还原→B3 低解释密度版本）双栏对照，点击任一步显示对应提问句式 ② **三个结构性副作用警示卡**：解释过强压扁不确定性 / 抽象稀释经验密度 / 对抗性成为默认，每卡一个"警惕点"与一个"制衡动作" ③ **总检验问题**页脚常驻："在承认这些不确定性之后，我是否还愿意暂时持有这个判断？"（是/否两个按钮，点击后不存数据，只显示一句回应） |

### 6.3 关联与反链

- 每个子页页脚固定显示 **"← 上一相关页 | 体系位置 | 下一相关页 →"**，相邻关系由体系结构决定（如"批判性思维 ←→ 讨论基线"）。
- 全局顶部有**关联图谱**入口：力导向图展示 7 子页 + 六层之间的双向关系边（如"讨论基线 → 对话实践：提供退出判断；对话实践 → 批判性思维：实践审辨"），节点可点击跳转。关系边的数据与页脚反链同源（同一份 JSON 中的 relations 字段），保证全站一致。

## 八、视觉设计：深空工作台

### 8.1 设计语言

- **基调**：深空工作台——深蓝黑底（#0A0E17）+ 星尘噪点（CSS 生成，非图片），白色文字为主、低饱和辅助色。
- **隐喻**：认知系统是一座运行在深空中的工作台，每一层是一台校准好的仪器，主循环是绕台运行的轨道。深色底让"光谱色分层"和"银白对话接口"的对比成立。
- **与内容的关系**：体系从"审辨"走向"判断"，对应光谱从冷到暖——冷色代表纪律与怀疑，暖色代表承诺与行动。这一温度变化本身就在讲述体系的故事。

### 8.2 色彩系统：六层光谱

| 元素 | 色值 | 语义 |
|---|---|---|
| 第零层 · 元层 | `#A78BFA`（紫罗兰） | 光谱之外的"校准光"：自省与制衡 |
| 第一层 · 认知原则 | `#6366F1`（靛） | 冷静的审辨纪律 |
| 第二层 · 问题处理 | `#3B82F6`（蓝） | 结构化的清晰 |
| 第三层 · 讨论机制 | `#22D3EE`（青） | 协议的透明 |
| 第四层 · 执行机制 | `#34D399`（绿） | 流程的稳定运行 |
| 第五层 · 最终能力 | `#FBBF24`（琥珀） | 判断落地时的温度 |
| 对话接口 | `#F8FAFC`（银白） | 与真实世界交换数据的"接口" |
| 背景 / 文字 | `#0A0E17` / `#E5E9F0` | 深空底 / 主文字 |

> 色彩仅作分层与状态区分；所有关键信息同时以文字、形状或线型表达，不依赖色觉（满足可访问性）。

### 8.3 字体与排版

- 标题：思源宋体 / Noto Serif SC（衬线，典籍与思辨感），如不可用回退 serif。
- 正文：思源黑体 / 系统无衬线栈，正文 ≥ 14px，行高 1.7。
- 强调：引用块（金句）用琥珀色左边框 + 大字号；术语用弱高亮而非变色。

### 8.4 动效规范

- 一切动效服务于"揭示结构"，禁止纯装饰动画。
- 层切换：垂直升降（钻取感）；主循环：轨道行进；卡片：淡入上移。
- **动画必须可暂停、可重置**（播放器控件、暂停键）；无自动循环空转。
- 动效时长 ≤ 400ms，尊重系统"减弱动态效果"设置。

### 8.5 组件库（统一实现）

层堆栈（可钻取）、循环步进器（播放/暂停/步进）、根问题卡片（聚合展开）、子页入口卡、论点折叠卡、抽屉面板、精度滑块、检查清单（勾选评分）、轮盘（扇区聚焦）、拖拽排序条、三语境切换器、反链导航条、关联图谱（力导向）、足迹回放条。所有组件统一尺寸体系（4px 栅格）、统一交互状态（默认/悬停/聚焦/选中/禁用）。

## 九、技术实现方案

### 9.1 技术选型

| 项 | 选型 | 理由 |
|---|---|---|
| 交付形态 | 多文件站点（可打包为单 HTML 交付） | 内容量大、便于维护；最终交付可产出一个自包含 index.html |
| 框架 | 原生 HTML/CSS/JS（零框架） | 无构建步骤、无依赖锁定，长期可维护 |
| 图表 | ECharts（CDN：jsDelivr），力导向图用 ECharts graph 系列 | 关联图谱、关系图；CDN 失败时回退为静态列表 |
| 路由 | hash 路由（`#/`、`#/topic/critical-thinking`） | 单文件可用、可分享深链 |
| 数据 | `data.js`：8 份总结的结构化 JSON | 一源多用（叙事/卡片/图表/清单/组件五种渲染） |
| 存储 | localStorage（仅存足迹与自省回答，不采集任何个人信息） | 自省模式与足迹回放 |

### 9.2 数据驱动架构（核心）

```
data.js（单一事实来源）
├── system          // 六层 + 对话接口：层名 / 解决的问题 / 核心概念 / 工具箱 / 关键词 / 颜色
├── loop            // 11 步主循环：步骤名 / 所在层 / 一句话说明
├── rootQuestions   // 4 个根问题：名称 / 聚合的层 / 聚合的子页
├── topics          // 7 个子页：页名 / 来源文档 / 一句话核心 / 论点卡组 / 特色组件数据 / 坐标
├── relations       // 页面间关系边（反链与关联图谱共用）
└── meta            // 全站文案、来源清单、版本
```

渲染层（components.js）只负责"把某份数据渲染成某组件"，不持有任何内容事实。**新增内容 = 改 data.js，不动渲染层**——这是"工程化思维"在内容生产上的直接落地。

### 9.3 性能与兼容

- 桌面优先（≥1024px 全功能），平板/手机自动折叠为单列堆叠，组件等宽换行。
- 交互组件支持键盘操作（Tab 聚焦、Enter 激活、方向键调节滑块）；触屏点击等效。
- 图片为零（全部 CSS/SVG 绘制），首屏加载 < 300KB。
- JS 失败降级：页面在无脚本时仍显示全部静态文本与静态层结构（初始 HTML 即包含全部信息，交互只是增强）。

### 9.4 建议目录结构

```
thinking-system-site-doubao/
├── 思考与判断体系交互网站设计方案-doubao.md   ← 本文档
├── 主页概念预览.html                          ← 主页交互概念演示
└── site/                                     ← 未来正式站点
    ├── index.html
    ├── css/style.css
    ├── js/data.js        # 内容数据（单一事实来源）
    ├── js/router.js      # hash 路由
    ├── js/components.js  # 统一组件库
    └── js/views/         # 各子页视图（7 个）
```

## 十二、验收标准（建议方案是否成立的判断清单）

- [ ] **全貌可见**：进入主页不点击、不滚动超过一屏，即能说出体系有"六层 + 一条循环 + 四个根问题"。
- [ ] **精髓可达**：任取一个子主题，2 次点击内到达；页头一句话核心可在 5 秒内读完并理解。
- [ ] **交互增值**：所有交互都"揭示新状态或新信息"；关掉 JS 后页面仍可完整阅读。
- [ ] **信息可追溯**：每个页面标注来源总结文件名；图表数据与总结原文一致，无杜撰数字。
- [ ] **可操作**：主循环可播放/暂停/步进/重置；滑块、轮盘、拖拽、清单均有即时文字反馈。
- [ ] **自我一致**：反链、关联图谱、坐标面包屑三处关系数据同源，无冲突。
- [ ] **可访问**：键盘可完成全部主要操作；窄屏无溢出；动画遵循系统减弱动态设置。

## 十三、设计取舍与风险（如实说明）

| 取舍 | 选择 | 代价 | 缓释 |
|---|---|---|---|
| 单隐喻 vs 多隐喻 | 只保留"认知操作系统"一个主隐喻 | 可能显得"技术腔" | 视觉上以"深空工作台"缓和，文案多用主文档原话 |
| 深色底 vs 浅色底 | 深色底 | 长文阅读疲劳风险 | 正文区使用深灰面板（#101624）降低对比；提供"纸面模式"开关（浅色底，保留光谱色） |
| 内容密度 | 每页卡片可折叠 | 折叠后信息层级变深 | 卡面即结论（可独立理解），展开只是补充论据 |
| 交互复杂度 | 15 个特色组件 | 开发量较大、有"炫技"风险 | 每个组件必须有 6.2 节标注的"内容依据"，无依据的交互一律不做 |
| 自省模式的隐私 | 足迹与回答仅存 localStorage | 换设备不保留 | 明示"仅本机存储"，不留服务器 |
