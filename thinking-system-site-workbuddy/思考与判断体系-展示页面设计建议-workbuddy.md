# 「思考与判断体系」展示网站——设计建议方案

> **版本**：workbuddy 版 · 设计提案 V1（待确认后实施）
> **素材**：`thinking_docs/` 下 8 份 `*-总结.md`（1 份主体系总结 + 7 份子主题总结）
> **发布方式**：静态多页站点，纯展示，无后端
> **核心理念**：「把体系做成可探索的认知地图」——既一眼看全，也能钻进任一层读透

---

## 一、目标与场景

**不做的事情**：不是把 8 份 markdown 原样搬上网。

**要做的事情**：

1. **展示体系全貌**：主页以一张可交互的全景图呈现「第零层元层 + 五层体系 + 对话应用层 + 回路迭代」结构，让读者 60 秒内理解这套认知系统在哪里、要解决什么；
2. **探索子主题精髓**：每个子主题一个独立页面，保留「一句话核心 → 推进脉络 → 核心论点 → 可复用产出」的层次结构，支持由概览向细节自然下钻；
3. **保持语言同构**：页面组织概念直接复用体系自身的概念——「层级 / 链条 / 闭环 / 制衡 / 回路」既是站点结构，也是内容主题。

**三类使用场景全部覆盖**：

| 场景 | 时长 | 入口 |
|---|---|---|
| **速览** | 3 分钟 | 主页全景图 + 主线一句话 |
| **精读** | 15-30 分钟 | 进入任意子页 → 一句话核心 → 核心论点 → 产出物 |
| **回查** | 1 分钟 | 文档索引表格 + 子页锚点导航 |

## 二、定位差异（与 qwen 版的取舍）

| 维度 | qwen 版 | workbuddy 版（本方案） | 取舍说明 |
|---|---|---|---|
| 主页叙事节奏 | Hero（文字）→ 图 → 索引 | **图先于文**——以全景图作为视觉锚点开局 | 全景图本身就是体系最浓缩的呈现，先看图再用文字解释更符合"先建立直觉" |
| 架构图实现 | HTML/CSS 层块 + flexbox 拼装 | **纯 SVG** 绘制，包含连接线、虚线回路、箭头 | SVG 能在任意一处精确控制几何，便于表达「贯穿色带」「回路」「分层折叠」 |
| 视觉语言 | 《经济学人》出版物感（衬线标题 + 克制红 + 浅米色底） | **现代信息板**（无衬线 + 大留白 + 冷色基底 + 单一暖色强调） | 信息板风格更符合现代阅读习惯，也更好承载交互态（hover/focus/active） |
| 数据/视图分离 | HTML 直接硬编码 | 引入 `assets/data/manifest.json` 描述页面清单与层结构 | 任何 AI 拿到 manifest 都能复刻一份相同站点，**降低跨 AI 协作的边际成本** |
| 工程化抓手 | 实施分期（V1/V2） | 数据 schema + 节点交互契约 | 让"加一个主题"成为改 manifest + 加 HTML 的简单动作，不依赖 JS 编程 |
| 强调色 | 深红 `#9E2B25` | **靛蓝 `#1F3A8A`** + 砖橙 `#C2410C` 作第二色 | 蓝主更冷静，橙用于回路与"持续迭代"等少数关键点，与"认知系统"的克制气质匹配 |
| 响应式 | 1100px 不破版即可 | 同等，桌面优先 | 与您既有内网站点约定一致 |

## 四、主页设计（核心：SVG 全景图驱动）

### 4.1 首屏：图先于文

开屏即一张 SVG 全景图占据中央视觉位（视口宽度的 92%，高宽比约 1:1.3 竖构图）。图下方紧跟两行说明文字：

> **思考与判断体系**
> *不是给自己建立一套"正确答案"，而是建立一套能够不断产生、检验和修正答案的系统。*

**为什么先图后文**：这套体系的精华就在结构关系（层级、贯穿、回路）；先用图建立空间直觉，再用文字解释每一处，比"先讲概念再看图"更接近体系本来的认知方式。

### 4.2 SVG 全景图（页面核心）

自上而下的层级结构，对应完备版总图。SVG 内部分为三组：

```text
[组 1] 第零层 · 元层（淡灰描边，可折叠）
   │
[组 2] 第一层 · 认知原则（横向贯穿色带=「批判性思维」）
   ↓
[组 3] 第二层 · 问题处理（结构化思维）
   ↓
[组 4] 第三层 · 讨论机制（基线+框架+模型）
   ↓
[组 5] 第四层 · 执行机制（工程化思维）
   ↓
[组 6] 第五层 · 最终能力（个人判断体系）
   ↓
[组 7] 对话 = 应用与测试场（八步横向流程）
   ↺ 回路虚线回到第零层
```

**绘制要点**：

- 每层 = 一个圆角矩形（rx="12"），层名左对齐、章节号右上小字；
- 箭头用 SVG `<marker>` 元素，沿垂直中线分布；
- 「批判性思维贯穿全程」用一条贯穿全图的细色带表示（不是某个层，是**贴边贯穿的纵条**）；
- 回路用动画虚线（CSS `stroke-dashoffset` 动画，可关闭以节能）；
- 每层 `data-layer-id` 属性 = 子页文件名 slug，点击跳转；hover 高亮 + 显示一句话定位 tooltip。

**交互行为**：

- **渐进下钻**：hover 显示该层一句话 → click 高亮+展开子标签 → 再次 click 跳转子页；
- **键盘可达**：每层是 `<a>` 元素，tab 顺序与体系顺序一致；
- **URL hash 定位**：`#layer-1` 直接滚动到对应层，配合浏览器历史便于分享；
- **分层折叠开关**：右上角按钮折叠元层（可减少首屏噪声）。

### 4.3 主页其余区块（按阅读路径自上而下）

| 区块 | 用途 | 关键交互 |
|---|---|---|
| **Hero 标题 + 主线一句话** | 一句话定义整套体系 | 无 |
| **SVG 全景图** | 体系全貌 | hover/click/键盘 |
| **四个根问题卡片** | 按"我如何知道 / 我如何思考 / 我如何判断 / 我如何校准"四问入口 | 卡片点击进入对应主题 |
| **主线流程条** | 从"面对现实"到"循环迭代"的完整路径（12 步） | hover 显示对应主题，hot 步骤（第 2、9、12 步）红色描边 |
| **六层链条表格** | 主页"速览"对照 | 表格行 hover 联动全景图高亮对应层 |
| **文档索引表格** | 回查入口 + 全站 sitemap | 同上 |

> 关键设计：**表格行与全景图的 hover 联动**——读者从"概览"切到"细节"或反向切回时，视觉锚点始终保持一致，体验远优于两个孤立区块。

## 五、子页面统一模板

七个子页共用一套版式骨架（一致导航、面包屑、页脚），内容区按各主题天然结构分节：

```
┌ 顶栏：站名 + 七层导航条（当前层高亮 + 进度指示）
├ 面包屑：主页 / 第N层·层名 / 篇名
├ Hero：篇名 + 一句话核心（大字引文 + 左侧 4px 强调色竖线）
├ 推进脉络：原文档的问答/阶段演进，纵向步骤线
├ 核心论点：分节卡片/表格（保留总结中的表格与模型图）
├ 可复用产出：清单式卡片（六问基线、五模板、四层构造等）
├ 与体系的关系：固定右下角的"微缩全景图"——高亮当前主题位置
└ 页脚：上一篇/下一篇（按体系顺序）+ 返回全景
```

### 5.1 子页"微缩全景图"——位置感的关键设计

每页右下角浮动一枚 140×180px 的小号 SVG 全景图，**当前主题所在层用色填充，其他层用淡灰**。在任何子页，读者都随时知道自己身在体系的何处——这是"探索感"的来源。

### 5.2 各子页专属交互模块（按内容特点定制）

| 子页 | 定制模块 |
|---|---|
| 批判性思维 | 「六问最小模型」做成可逐条点亮的清单；「批判 vs 怀疑 vs 审辨」三栏对比 |
| 结构化 × 工程化 | 三类模型层级链的纵向流程图；四层抽象模型做可点击分层（默认示例：冰箱制冷系统） |
| 讨论基线 | 四基线顺序流程 + 精度宽容度对比表；「退出讨论 ≠ 认输」单独卡片 |
| 对话 | 七步交流模型步骤条；三语境切换标签（职场 / 亲密 / 公共） |
| 判断体系 | 四层构造堆叠图；证据排序的可视化（堆叠条状图：逻辑 / 数据 / 经验 / 权威） |
| 双轨引擎 | **A/B 双轨对照布局（左右分栏，中间放置「总检验」问题）**——版式本身即内容 |
| 结构化笔记 | 还原「笔记模板」卡片样式 + 说明其作为跨会话记忆锚点的用法 |

## 六、视觉规范

### 6.1 风格基调：现代信息板

**视觉气质**：干净、克制、信息密度高、可静读长文。追求"读得下去的版式"，不追求"科技感""未来感"。

### 6.2 配色（CSS 变量化）

| 用途 | 色值 | 说明 |
|---|---|---|
| 纸底 | `#FAFAF7` | 微暖白，避免纯白刺眼 |
| 卡底 | `#FFFFFF` | 与纸底形成微差层级 |
| 正文墨色 | `#0F172A` | 近黑加蓝，长文阅读友好 |
| 次级文字 | `#64748B` | 标注、来源、辅助说明 |
| 主强调色 | `#1F3A8A`（靛蓝） | 层级标题、当前高亮、链接 hover |
| 第二强调 | `#C2410C`（砖橙） | 用于回路、持续迭代、关键提问 |
| 分隔线 | `#E5E7EB` | 细规则线，区块分隔主力 |
| 层级色带 | 6 层各一个低饱和色相 | 全景图与子页导航共用，形成"层=色"的全站记忆 |
| 元层色 | `#A8A29E`（暖灰） | 元层刻意去色化，强调"元"层是另一种关注 |

> 与 qwen 版差异：本方案以蓝为主、橙为辅，更冷静；qwen 版以红为主、蓝为辅，更热。

### 6.3 字体与排版

- **标题**：无衬线（system-ui / -apple-system / "PingFang SC"），weight 600；
- **正文**：无衬线，行高 1.75，栏宽 68ch；
- **引言/一句话核心**：大号（1.875rem）weight 500 + 左侧 4px 主色竖线；
- **表格**：细线三线表（顶/表头/底线），zebra 行底色 `#F8FAFC`；
- **图表标注**：小字号（0.8125rem）`#64748B` + 编号（图 1 / 图 2），出版物惯例。

### 6.4 响应式

- 桌面优先（≥ 1280px 最佳）；
- 1100px 以下：栅格降为单列；SVG 全景图改 `width: 100%; height: auto`；
- 不深度适配移动端，与您既有内网站点约定一致。

## 七、技术方案（最小依赖优先）

### 7.1 技术栈

- **HTML5 + CSS3 + 原生 JavaScript（ES2022）**——零框架、零构建、零 npm；
- **字体**：系统字体栈（`-apple-system, BlinkMacSystemFont, "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", sans-serif`），离线可开；
- **图标**：纯 SVG 内联（不做 icon 库依赖）；
- **架构图**：手写 SVG（圆角矩形 + marker 箭头 + dasharray 动画），交互用原生 `addEventListener`；
- **微缩全景图**：复用主页 SVG 的简化版（仅外轮廓 + 颜色态不同）。

### 7.2 数据/视图分离——这是与 qwen 版的工程差异

引入 `assets/data/manifest.json`，描述：

```json
{
  "site": { "title": "思考与判断体系", "version": "1.0" },
  "pages": [
    { "id": "critical-thinking",       "title": "批判性思维",        "layer": 1, "prev": null,                "next": "structured-engineering" },
    { "id": "structured-engineering",  "title": "结构化×工程化×模型", "layer": 2, "prev": "critical-thinking",  "next": "discussion-baseline" },
    { "id": "discussion-baseline",     "title": "讨论问题的基线",    "layer": 3, "prev": "structured-engineering", "next": "dialogue" },
    { "id": "dialogue",                "title": "批判性思维的对话",  "layer": "app", "prev": "discussion-baseline", "next": "judgment-system" },
    { "id": "judgment-system",         "title": "判断体系",          "layer": 5, "prev": "dialogue",            "next": "metacognition" },
    { "id": "metacognition",           "title": "双轨引擎",          "layer": 0, "prev": "judgment-system",     "next": "notes" },
    { "id": "notes",                   "title": "结构化笔记",        "layer": 4, "prev": "metacognition",       "next": null }
  ],
  "layers": [
    { "id": 0, "name": "元层 · 自反与制衡",    "color": "#A8A29E", "collapsed_default": true },
    { "id": 1, "name": "第一层 · 认知原则",    "color": "#1F3A8A" },
    { "id": 2, "name": "第二层 · 问题处理",    "color": "#0E7490" },
    { "id": 3, "name": "第三层 · 讨论机制",    "color": "#15803D" },
    { "id": 4, "name": "第四层 · 执行机制",    "color": "#A16207" },
    { "id": 5, "name": "第五层 · 最终能力",    "color": "#C2410C" },
    { "id": "app", "name": "应用层 · 对话",    "color": "#7C3AED" }
  ]
}
```

**收益**：

- **加一页只动 4 处**：① 加 HTML；② 在 manifest 加 entries；③ nav.js 读 manifest 渲染导航；④ 各子页微缩图读 manifest 决定高亮；
- **任何 AI 看到 manifest 都能复刻相同站点**——把体系内容"结构化沉淀"，正是这套体系第四层工程化思维在站本身的应用；
- **页面顺序调整不动代码**，改 manifest 即可。

### 7.3 目录结构

```
thinking-system-site-workbuddy/
├── index.html
├── critical-thinking.html
├── structured-engineering.html
├── discussion-baseline.html
├── dialogue.html
├── judgment-system.html

└── assets/
    ├── css/site.css
    ├── js/nav.js
    ├── js/diagram.js
    └── data/manifest.json
```

### 7.4 一些工程细节契约

- **页面标识**：每个 HTML 的 `<body data-page="X">`，nav.js 据此判定当前页与上一篇/下一篇；
- **目录式锚点**：每个子页内的章节固定 `id="sec-N"`，跳转链接形如 `critical-thinking.html#sec-2`；
- **微缩图同步**：nav.js 在主页图与子页微缩图之间共享同一 SVG 字符串模板，只替换 highlight 状态；
- **可访问性**：每层 `<a>` 含 `aria-label="第N层：xxx，回答 xxx 问题"`；SVG 加 `<title>` 与 `<desc>`；
- **打印样式**：`@media print` 下隐藏导航条与回路动画，保留文字与表格，便于沉淀 PDF。

## 八、实施分期

### V1（首批交付）

1. `site.css` + `nav.js` + `manifest.json` 骨架；

   - HTML 引用的 class/ID 与 CSS 逐项核对；
   - JS 用 `node --check` 语法校验；
   - 桌面浏览器（Chrome/Safari）截图走查主页全景图交互；
   - 表格行 hover 与全景图联动的可达性（键盘 tab 测试）。

## 九、待您确认的决策点

1. **强调色**：本方案默认 **靛蓝 `#1F3A8A` 为主、砖橙 `#C2410C` 为辅**（更冷静），还是希望改回 qwen 版的 **深红为主、蓝为辅**（更热）？
2. **主页首屏首块**：本方案默认 **全景图先于文字标题**（图先于文，建立空间直觉），还是希望 **先标题后图**（更传统稳妥）？
3. **manifest.json 是否需要**：本方案默认引入（数据/视图分离是工程化思维在站本身的应用），还是希望 **保持纯 HTML 直写**（更接近 qwen 版、最简）？
4. **暗色主题**：V1 是否一并交付（default light + 可切换 dark）？还是 V1 只做 light，V2 再加？

## 十、可被复刻性（这是 workbuddy 视角的元设计）

最后留一点值得专门说明的元设计：

这套站点本身是**它所描述的体系的一个实例**——

- 第二层结构化思维 → 站点的信息架构（page ↔ layer 映射）就是结构化拆解；
- 第三层讨论机制 → 站点的六基线（标题层级、可读性、术语一致、章节对应、来源标注、呼应总结）就是在写入页面时实际遵循的基线；
- 第四层工程化思维 → manifest.json + nav.js 自动渲染导航，是把"按页维护顺序"这种依赖临场能力的劳动，转换为可重复流程；
- 第五层判断体系 → 关于"先图后文还是先文后图""强调色是冷是暖"等决策，都明确写在"决策点"小节，让判断过程可被检视；
- 第零层元层 → 增设「可被复刻性」一节，把站点本身当作被反优势机制审视的对象——是不是"为了不同而不同"地强求差异化？是不是过度工程化？

因此这个站点不只是"展示"体系，而是**演示**体系。
